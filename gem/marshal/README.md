# Marshal

This package registers the Go-backed `Marshal` module as the lazy gem `marshal`. Import `github.com/oruby/oruby/gem/marshal` to register it and activate it with `mrb.Resolve("marshal")`; `gem/stdlib` includes the registration. The format implementation follows MRI Marshal 4.8 and the format behavior of [`take-cheeze/mruby-marshal`](https://github.com/take-cheeze/mruby-marshal) at commit `a15abaa0d4bcdede36d0ca6a589135e03779cac6`, ported to Go and ORuby APIs without C++ or Oniguruma.

The provider implements `Marshal.dump`, `Marshal.load`, `Marshal.restore`, and the `MAJOR_VERSION`/`MINOR_VERSION` constants. Supported values include MRI 30-bit fixnums and arbitrary-size integers mapped to ORuby's Go-backed `Bignum`, floats, symbols, strings, arrays, hashes with value defaults, ranges, exceptions, named classes/modules, ordinary objects with instance variables, Structs, and Go-backed Regexp values. It supports `marshal_dump`/`marshal_load` and `_dump`/`_load` hooks. IO-like objects with `write` or `read(length)` can be used for streaming.

This is a compatibility subset, not a complete MRI implementation. String instance variables remain unsupported because the configured mruby `RString` has no instance-variable table and its runtime rejects `mrb_iv_set` on strings; MRI streams containing those fields fail explicitly rather than writing outside the string allocation. Exception messages must be String or nil in ORuby, and mruby normalizes `Exception.new(nil)` differently from MRI; non-string exception messages cannot be restored faithfully. Arbitrary C-backed objects, Regexp encodings/options not represented by the Go regexp backend, and `Marshal.load` proc callbacks are also unsupported. Regexp instances with retained `@source` and `@options` metadata (for example, `Regexp.new`) are supported. ORuby may discard option bits on regexp literals before Marshal sees them; the gem cannot reconstruct lost flags, so such literal dumps can differ from MRI. String encodings are limited by ORuby's string/encoding support. The implementation enforces 64 MiB input/output, one million values, and a maximum nesting depth of 512 (default dump depth 256); this can reject otherwise valid MRI streams.

**Never use `Marshal.load` with untrusted data.** Loading resolves named constants, allocates objects, invokes custom hooks, and currently constructs Struct instances through their class constructor. Those actions can execute arbitrary Ruby code. Size limits are not a security sandbox and do not make untrusted Marshal data safe.
